## high: Validation-service overrides can inject process-control environment variables into ClawPatch children

id: fnd_sig-feat-library-04c78af7f0-7e3c_3e0bfc02d7
category: security
confidence: medium
triage: risk
status: open
feature: Python source src/clawpatch_supervise/:clawpatch (feat_library_04c78af7f0)

evidence:
- src/clawpatch_supervise/clawpatch_release.py:179-196 (_clawpatch_control_env_overrides)
- src/clawpatch_supervise/clawpatch_release.py:199-229 (_release_clawpatch_env)
- src/clawpatch_supervise/clawpatch_release.py:256-274 (_run)

Validation rejects only malformed names, Python import variables, and a small policy-owned set. It accepts PATH, PATHEXT, LD_PRELOAD, DYLD_* and NODE_OPTIONS, then overwrites the sanitized child environment. Repository-influenced validation-service output could therefore select an executable or load code with supervisor privileges.

recommendation:
Make process-control variables supervisor-owned. Resolve executable paths independently and reject executable-resolution, loader, runtime-hook, and shell-startup variables; preferably allow only explicitly declared service-connection variables.

test analysis:
No tests were linked or included for this feature, so no visible test establishes rejection of process-control overrides.

suggested regression test:
Pass PATH, PATHEXT, LD_PRELOAD, DYLD_INSERT_LIBRARIES, and NODE_OPTIONS individually and assert SafetyError, while proving an allowed service variable remains accepted.

minimum fix scope:
Harden _clawpatch_control_env_overrides and add focused environment-policy tests.

repro:
Call _release_clawpatch_env with child_env_overrides containing PATH or NODE_OPTIONS; both values are accepted and returned for child execution.

## medium: Installer does not enforce the stdlib-only runtime dependency policy

id: fnd_sig-feat-config-cf96aef71d-cf376_ab0ba8115d
category: build-release
confidence: high
triage: risk
status: open
feature: Shell/workflow config install.sh (feat_config_cf96aef71d)

evidence:
- scripts/install.sh:265-268

The fresh environment installs the wheel without --no-deps or validation that its metadata contains no Requires-Dist entries. A mispackaged release could consequently install third-party packages from an index, violating the project's stdlib-only runtime policy and expanding its network and supply-chain exposure.

recommendation:
Use --no-deps and reject the installation before activation when the installed distribution metadata contains any Requires-Dist entries.

test analysis:
No tests were linked for this feature, and no supplied test exercises a dependency-bearing wheel or asserts that package-index access is prohibited.

suggested regression test:
Run the installer with a temporary wheel that declares a test dependency and assert that it fails without accessing a package index or activating either command.

minimum fix scope:
Change the pip invocation in scripts/install.sh, add a zero-runtime-dependencies metadata validation, and add an installer regression test.

repro:
Build a clawpatch-supervise wheel with a Requires-Dist entry, provide it through CLAWPATCH_SUPERVISE_SOURCE with its SHA-256, and run the installer; pip resolves and installs the declared dependency.

## medium: Machine-readable command output is corrupted by merging stderr into stdout

id: fnd_sig-feat-library-04c78af7f0-57cc_4d925b5405
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/clawpatch_supervise/:clawpatch (feat_library_04c78af7f0)

evidence:
- src/clawpatch_supervise/clawpatch_release.py:256-280 (_run)
- src/clawpatch_supervise/clawpatch_release.py:312-338 (_parse_json_output)
- src/clawpatch_supervise/clawpatch_release.py:535-539 (_process_repository_root)

_run appends stderr to stdout even when a command succeeds. Consumers parse the combined value as JSON or as one filesystem path. A benign warning can make valid JSON ambiguous or turn a valid Git root into a nonexistent path, which can make repository process ownership checks miss an active process.

recommendation:
Preserve stdout and stderr separately. Parse stdout only and add separately redacted stderr to diagnostics after a failure.

test analysis:
No linked tests were supplied, and no visible test exercises successful commands that also produce stderr.

suggested regression test:
Simulate successful git and JSON commands with valid stdout plus warning text on stderr and assert parsing uses stdout unchanged.

minimum fix scope:
Change _run to retain separate streams and update machine-readable consumers and tests.

repro:
Return successful command output with stdout '/repo\n' and stderr 'warning'; after merging, _process_repository_root resolves the combined string rather than /repo.

## medium: README documents obsolete external handling of uncertain findings

id: fnd_sig-feat-library-b1f67be94d-9bbd_d3096414b8
category: docs-gap
confidence: high
triage: docs-gap
status: open
feature: Python project clawpatch-supervise (feat_library_b1f67be94d)

evidence:
- README.md:172-173
- README.md:196-197
- README.md:205-206
- README.md:213-214

The README says the external unattended command must remain on an uncertain finding and cannot advance. The governing project contract permits that command to commit an applied repair, advance to the next open finding, and retain and report the uncertainty honestly; only strict library mode retains the old stop behavior. The published CLI documentation therefore misstates a material queue-processing contract.

recommendation:
Update every uncertain-outcome description to distinguish external unattended behavior from strict library behavior. Clarify that retained uncertainty still prevents completion proof and exit 0.

test analysis:
No linked tests are included for this feature, and runtime tests would not ordinarily detect stale documentation.

suggested regression test:
Add a documentation-contract test asserting that the README describes external uncertain advancement, strict-library retention, and nonzero completion while uncertainty remains.

minimum fix scope:
README.md uncertain-outcome and completion descriptions.

## medium: Windows process preflight is global and does not recognize the supervisor executable

id: fnd_sig-feat-library-04c78af7f0-3db4_71587618b1
category: concurrency
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/clawpatch_supervise/:clawpatch (feat_library_04c78af7f0)

evidence:
- src/clawpatch_supervise/clawpatch_release.py:458-468 (_is_clawpatch_argv)
- src/clawpatch_supervise/clawpatch_release.py:610-645 (_windows_clawpatch_processes)
- src/clawpatch_supervise/clawpatch_release.py:648-653 (_require_no_process)

The Windows branch returns every matching ClawPatch process without establishing its repository, so an unrelated repository can cause a false busy failure. Its PowerShell regex also omits clawpatch-supervise and clawpatch-supervise.exe, although the platform-independent detector recognizes them, creating a detection gap.

recommendation:
Establish each candidate's working directory and repository, reuse equivalent executable-recognition rules across platforms, and fail closed only when an actual candidate's ownership cannot be determined.

test analysis:
No Windows process-detection tests were linked or included.

suggested regression test:
Mock same-repository clawpatch-supervise.exe, other-repository clawpatch.exe, and unrelated processes; assert only the same-repository supervisor is returned.

minimum fix scope:
Replace or extend _windows_clawpatch_processes and add repository-scoping and executable-name tests.

repro:
On Windows, run clawpatch in repository A and check repository B; B is reported busy. A clawpatch-supervise.exe command does not match the current PowerShell regex.

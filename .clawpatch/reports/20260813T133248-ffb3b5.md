## high: Repository-idle detection misses supervisors launched with --repo from another directory

id: fnd_sig-feat-library-04c78af7f0-3f6b_cb142aa0f9
category: concurrency
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/clawpatch_supervise/:clawpatch (feat_library_04c78af7f0)

evidence:
- src/clawpatch_supervise/clawpatch_external.py:468-505 (main)
- src/clawpatch_supervise/clawpatch_release.py:549-623 (_is_clawpatch_argv)
- src/clawpatch_supervise/clawpatch_release.py:633-680 (_active_clawpatch_processes)

The CLI can target an arbitrary checkout through --repo, but active-process detection associates recognized processes only with their cwd. A supervisor started elsewhere while targeting this repository is omitted, permitting overlapping queue, checkpoint, Git, or repair operations.

recommendation:
Parse --repo and --repo= for supervisor processes, resolve relative targets against their cwd, and compare the resulting Git root. A repository-scoped exclusive lock would also close process-scan races.

test analysis:
No linked tests covering a --repo target different from process cwd were supplied.

suggested regression test:
Model or launch a supervisor with cwd=/tmp and --repo=/target/repo, then assert it is active for /target/repo.

minimum fix scope:
Correct target-repository resolution in clawpatch_release.py and add focused process-detection tests.

repro:
From /tmp, run clawpatch-supervise --repo /target/repo. _active_clawpatch_processes(Path("/target/repo")) excludes it because /tmp is not the target Git root.

## high: Windows command resolution ignores the child environment's vetted PATH

id: fnd_sig-feat-library-04c78af7f0-ad12_9d33aede4f
category: security
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/clawpatch_supervise/:clawpatch (feat_library_04c78af7f0)

evidence:
- src/clawpatch_supervise/clawpatch_release.py:285-320 (_release_clawpatch_env)
- src/clawpatch_supervise/clawpatch_release.py:347-380 (_run / _platform_command)

On Windows, _platform_command calls shutil.which before CommandRunner receives the supplied child environment. Resolution therefore uses the ambient PATH instead of the preflight-selected child PATH and can execute a different ClawPatch binary.

recommendation:
Pass the effective child PATH into _platform_command and call shutil.which with that explicit path.

test analysis:
No linked tests or Windows PATH-resolution assertions were supplied.

suggested regression test:
Assert that Windows resolution selects clawpatch exclusively from env["PATH"], not os.environ["PATH"].

minimum fix scope:
Update _run and _platform_command and add a Windows regression test.

repro:
Put different clawpatch.cmd files on the ambient PATH and env["PATH"], then call _run(["clawpatch"], env=env). The ambient executable is resolved.

## medium: npm can come from a different toolchain than the validated Node.js 22 executable

id: fnd_sig-feat-config-cf96aef71d-9a409_49e4e3f5ee
category: build-release
confidence: high
triage: risk
status: open
feature: Shell/workflow config install.sh (feat_config_cf96aef71d)

evidence:
- scripts/install.sh:141-166

The script validates one absolute Node.js executable but discovers and invokes npm independently through the original PATH. An earlier PATH directory can therefore supply an unrelated npm, causing installation failure or an unintended npm/Node pairing despite satisfying the Node.js requirement.

recommendation:
Resolve npm to an absolute path with node_dir prioritized, then invoke it with node_dir first in PATH so it uses the validated Node.js executable.

test analysis:
No tests were linked for this installer feature, including mixed-toolchain PATH ordering.

suggested regression test:
Run the installer with an unrelated npm earlier in PATH than a complete Node.js 22 toolchain and assert that the npm adjacent to the validated node is used.

minimum fix scope:
Update npm resolution and both npm invocations in scripts/install.sh, then add one PATH-ordering regression test.

repro:
Place a failing npm shim in an earlier PATH directory and a complete Node.js 22 toolchain later in PATH, ensure no compatible clawpatch exists, and run the installer. Node.js validation succeeds, but the unrelated npm handles npm pack.
